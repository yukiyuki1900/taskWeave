# 五分钟演示与面试讲解

开场先说明：这是一条固定脚本驱动的工程能力演示，不是模型效果评测；页面只读，执行仍在 CLI/Runtime，演示确认由脚本代行。

1. **0:00—0:40：统一任务内核。** 展示依赖图。需求、代码、测试、文档是不同任务预设，共享 Agent Loop、工具、预算、持久化和验收；不把四类任务包装成四套独立 Agent。
2. **0:40—1:20：生成与验收分离。** 跳到阶段 02，展示需求产物与验证记录。结构检查通过不等于业务确认，节点仍停在 waiting_acceptance。
3. **1:20—2:00：失败与重试。** 跳到阶段 03，点击 implementation，打开“验证与验收”；实际 smoke 失败，tests 阻塞。阶段 05 展示新 attempt、已通过检查，以及文档 ask_user。强调不是在 Web 中点击了重试按钮。
4. **2:00—2:50：上下文与 Skill。** 阶段 06 选择 documentation。打开“摘要与交接”，指出来源 node/attempt/task、验证 ID 和产物 hash；摘要标为提取式。打开 Skill，展示绑定版本和 hash，说明不会增加工具权限，也没有证明真实模型已理解内容。
5. **2:50—3:40：返工与历史。** 跳到阶段 09，选择 requirements 的第一个历史 attempt，再打开旧需求 JSON。页面显示产物已变化与两个 hash，不能用当前文件冒充历史结果。回到阶段 08 看下游被传递失效。
6. **3:40—4:30：可观测性。** 跳到阶段 12，比较当前/全部 attempt。9 次尝试包含失败、重试与返工消耗；时间和人工操作仍是全运行口径。Token 为 0 是因为没有调用模型，统计中的确认动作由脚本代行。展示事件序号与 warnings，不声称不完整时间已被精确统计。
7. **4:30—5:00：边界与下一步。** 当前是本地单用户、固定 DAG 串行调度、文件持久化。没有并行隔离、分布式租约、历史产物版本库或 Web 控制面。下一步用固定真实模型和人工标准做多轮基线，再依据瓶颈推进隔离与服务化。

建议预先打开静态演示，并保留失败、交接和历史产物三个页签链接。不要演示中临时填 Key 或展示个人工作区；本仓库的公开录制可以完整讲解上述能力。

可回答的追问：为什么结果绑定 attempt、为什么验证是独立阶段、返工如何传递失效、如何避免工具重复执行、摘要证据证明了什么、Skill 的版本为什么必须绑定，以及为什么只读 Web 不直接操作文件存储。用对应源码和记录回答，不把尚未实现的能力当作当前设计成果。
